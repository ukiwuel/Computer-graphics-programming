# Лабораторная работа 2. Чтение информации из графических файлов

## 1. Назначение программы

Приложение для Windows на Python с интерфейсом Tkinter. Пользователь выбирает папку и при необходимости включает обработку подпапок. Программа отбирает файлы с расширениями `.jpg`, `.jpeg`, `.gif`, `.tif`, `.tiff`, `.bmp`, `.png`, `.pcx`, определяет реальный формат по сигнатуре и выводит характеристики в таблицу. Поддерживается обработка папок с большим количеством файлов, в том числе до 100 000.

В таблице отображаются:

- **Файл** — имя файла.
- **Размер (px)** — ширина и высота в пикселях.
- **DPI** — горизонтальное и вертикальное разрешение, если оно записано в файле.
- **Глубина цвета (бит)** — число бит на пиксель по данным заголовка/метаданных.
- **Сжатие** — метод, указанный форматом или его заголовком.
- **Формат** — формат, определённый по содержимому файла, а не только по расширению.
- **Статус** — результат проверки структуры.
- **Дополнительно** — дополнительные сведения о кодировании и структуре файла.

Интерфейс включает выбор папки, переключатель подпапок, запуск и остановку анализа, прогресс-бар, счётчик обработанных файлов, сортировку по заголовкам столбцов, вертикальную и горизонтальную прокрутку, изменение размеров окна и красную подсветку ошибок.

## 2. Библиотеки и способ чтения данных

Метаданные считываются **вручную из байтов файла**. Сторонние библиотеки для разбора изображений не используются. Применяются только стандартные библиотеки Python:

- `os` — обход папок, получение размеров и имён файлов;
- `struct` не требуется: целые числа читаются функцией `int.from_bytes`;
- `threading`, `queue`, `concurrent.futures` — фоновые задачи и многопоточность;
- `tkinter` и `tkinter.ttk` — графический интерфейс;
- `time`, `re` — измерение времени и сортировка.

Программа не декодирует пиксельные данные и не загружает изображение целиком. При открытии файла `Src` сохраняет первые 8192 байта. Когда метаданные расположены дальше, чтение выполняется по смещению; для проверки завершающих маркеров читается конец файла. После анализа файловый дескриптор закрывается.

Функции `u16`, `u32`, `u64` и `s32` извлекают целые числа заданной разрядности с указанным порядком байтов. Функция `need` проверяет, что нужное количество байтов действительно доступно, и при обрыве структуры поднимает исключение `Corrupt`.

## 3. Определение формата

Формат определяется по сигнатуре в начале файла:

| Формат | Сигнатура/признак |
|---|---|
| PNG | `89 50 4E 47 0D 0A 1A 0A` |
| JPEG | начало `FF D8 FF` |
| GIF | `GIF87a` или `GIF89a` |
| BMP | `BM` |
| TIFF | `II 2A 00`, `MM 00 2A` либо варианты BigTIFF |
| PCX | допустимые значения производителя, версии, кодирования и глубины в заголовке длиной 128 байт |

Расширение используется только для отбора файлов. Если содержимое не соответствует расширению, программа показывает фактический формат и предупреждение. Поэтому, например, текстовый файл с расширением `.jpg` не будет ошибочно принят за JPEG.

## 4. Как извлекаются основные характеристики

### 4.1. Размер изображения

| Формат | Источник |
|---|---|
| JPEG | маркер SOF (Start of Frame): высота, ширина и число компонентов |
| PNG | чанк IHDR: поля ширины и высоты |
| GIF | Logical Screen Descriptor: ширина и высота логического экрана |
| BMP | поля ширины и высоты DIB-заголовка; отрицательная высота означает порядок строк top-down |
| TIFF | теги IFD `ImageWidth` (256) и `ImageLength` (257) |
| PCX | координаты `Xmin`, `Ymin`, `Xmax`, `Ymax`; ширина и высота рассчитываются с учётом включённых границ |

### 4.2. Разрешение (DPI)

Если формат не содержит разрешение или оно не задано, выводится `—`.

| Формат | Источник и преобразование |
|---|---|
| JPEG | JFIF APP0: плотность X/Y и единица измерения. Для единицы «пикселей на сантиметр» значение умножается на 2,54. Также поддерживается чтение разрешения из EXIF/TIFF, если оно доступно |
| PNG | чанк `pHYs`: пикселей на метр. При единице «метр» значение умножается на 0,0254 |
| BMP | поля `biXPelsPerMeter` и `biYPelsPerMeter`; перевод из пикселей на метр умножением на 0,0254 |
| TIFF | теги `XResolution` (282), `YResolution` (283), `ResolutionUnit` (296). Единица 2 означает дюймы, 3 — сантиметры; единица без физического измерения не выводится как DPI |
| PCX | поля `HDpi` и `VDpi` в байтах 12–15 заголовка |
| GIF | стандартный формат GIF не хранит DPI, поэтому выводится `—` |

### 4.3. Глубина цвета

| Формат | Метод |
|---|---|
| PNG | из IHDR читаются битовая глубина и тип цвета. Для RGB/RGBA и серого с альфа-каналом учитывается количество каналов; для индексированного PNG выводится глубина индекса палитры |
| BMP | поле `biBitCount` DIB-заголовка; для 12-байтового OS/2 CORE-заголовка используются соответствующие смещения |
| GIF | глубина индекса цвета определяется по таблице цветов первого кадра — локальной, если она есть, иначе глобальной |
| TIFF | тег `BitsPerSample` (258), при необходимости умноженный на `SamplesPerPixel` (277); если заданы отдельные значения для каналов, они суммируются |
| PCX | значение `BitsPerPixel` на плоскость (байт 3) умножается на число плоскостей (байт 65) |
| JPEG | точность компонента и число компонентов извлекаются из SOF; глубина рассчитывается как произведение этих значений |

### 4.4. Сжатие

| Формат | Метод определения |
|---|---|
| JPEG | тип маркера SOF определяет режим кодирования, например baseline или progressive; название в таблице отражает тип кодирования JPEG, а не отдельное поле «сжатие» |
| PNG | метод сжатия из IHDR; стандартное значение 0 соответствует Deflate/zlib |
| GIF | LZW |
| BMP | поле `biCompression`: например, BI_RGB (без сжатия), RLE8, RLE4, Bitfields, JPEG или PNG |
| TIFF | тег `Compression` (259), например None, CCITT, LZW, JPEG, Deflate или PackBits |
| PCX | байт 2 заголовка: 1 означает RLE, 0 — несжатые данные |

## 5. Дополнительные сведения

Каждая дополнительная характеристика предназначена для пояснения способа хранения изображения:

| Сведение | Значение и источник |
|---|---|
| Тип цвета PNG и бит на канал | IHDR: показывает модель цвета (серый, RGB, палитра, серый+альфа, RGBA) и точность канала |
| Метод фильтрации PNG | поле метода фильтрации IHDR. Метод 0 использует один из пяти фильтров строк PNG |
| Adam7 | флаг чересстрочности IHDR; изображение организовано в семь проходов |
| Палитра PNG | чанк PLTE; содержит записи RGB, на которые ссылаются индексы пикселей |
| Палитра GIF | размер таблицы цветов вычисляется из упакованных полей заголовка или дескриптора кадра |
| Interlaced GIF | бит чересстрочности в Image Descriptor; строки кадра хранятся в четыре прохода |
| GIF87a/GIF89a | версия формата из первых шести байтов |
| Прозрачность GIF | признак прозрачного цвета в Graphic Control Extension |
| Анимация GIF | наличие Netscape loop extension отмечается как признак анимации/зацикливания |
| Top-down BMP | отрицательная высота DIB-заголовка означает хранение строк сверху вниз |
| Тип DIB-заголовка | размер и тип структуры заголовка BMP |
| JPEG baseline/progressive | тип SOF; progressive JPEG передаёт изображение несколькими проходами |
| Adobe APP14 / ICC | наличие соответствующих сегментов JPEG; это дополнительные сведения о цветовой интерпретации/профиле |
| Цветовая модель JPEG | оценивается по числу и идентификаторам компонентов, а также маркеру Adobe |
| Таблицы квантования JPEG | маркеры DQT; программа выводит количество найденных таблиц и точность элементов |
| PhotometricInterpretation TIFF | тег 262: интерпретация значений пикселей, например RGB, Palette, CMYK или YCbCr |
| Число страниц TIFF | количество связанных IFD, если их удалось последовательно прочитать; характеристики в таблице относятся к первой странице |
| Predictor TIFF | тег 317; указывает на предсказание, используемое при кодировании данных |
| PCX: версия и плоскости | поля версии и числа цветовых плоскостей заголовка |
| Несоответствие расширения | сравниваются расширение имени и формат, установленный по сигнатуре |

## 6. Проверка ошибок и повреждённых файлов

Ошибки отдельного файла не прерывают обработку остальных. В таблице отображается красная строка со статусом ошибки или предупреждением. Проверяются, в частности:

- пустые файлы и неизвестные сигнатуры;
- обрезанные заголовки и сегменты;
- некорректные значения ключевых полей размеров/глубины;
- выход данных или палитры за границы файла в проверяемых случаях;
- отсутствие завершающего маркера PNG `IEND`, JPEG `FF D9` или GIF `3B`;
- недостаточный размер данных для ряда BMP, TIFF и PCX структур.

Ошибки доступа при обходе папок пропускаются. Общая ошибка фонового анализа выводится в диалоговом окне.

**Ограничение валидации:** это проверка структуры и отдельных границ, а не полная проверка целостности каждого блока и всех пиксельных данных. Например, программа не декодирует содержимое изображения и не проверяет CRC каждого чанка PNG.

## 7. Производительность и многопоточность

- **Потоковое чтение.** Не загружаются целые изображения. Используется начальный буфер 8192 байта и чтение по смещениям, когда нужные поля расположены дальше; для конечных маркеров анализируется хвост файла.
- **Параллельная обработка.** Используется `ThreadPoolExecutor`; число рабочих потоков — до четырёх потоков на логическое ядро, но не более 32.
- **Отзывчивый интерфейс.** Обход папок и разбор файлов выполняются в фоновом потоке. Данные передаются в GUI через `queue.Queue`; главный поток Tkinter забирает их порциями до 300 событий примерно каждые 30 мс.
- **Индикация прогресса.** На этапе поиска файлов прогресс-бар работает в режиме indeterminate; после подсчёта файлов отображается число обработанных файлов из общего количества.
- **Остановка.** Кнопка «Стоп» устанавливает флаг остановки. Уже выполняющаяся операция чтения может завершиться прежде, чем остановка полностью вступит в силу.
- **Изменение размеров окна.** Таблица растягивается вместе с окном и занимает доступное пространство; при нехватке ширины доступны горизонтальная и вертикальная полосы прокрутки. Заголовки таблицы позволяют сортировать строки.

Фактическое время зависит от диска, числа файлов, их структуры и антивирусного сканирования. Значения производительности следует указывать только после замера на целевом наборе файлов.

## 8. Ограничения

- Для многостраничного TIFF показываются характеристики первой страницы.
- Для GIF размер относится к логическому экрану, а глубина цвета — к палитре первого найденного кадра.
- Формат выбирается по расширению только на этапе отбора; содержимое проверяется по сигнатуре. Файлы с неподдерживаемыми расширениями не сканируются, даже если внутри они являются изображениями.
- JPEG с нестандартными вариантами кодирования может содержать дополнительные особенности, которые текущий парсер не интерпретирует полностью.
- Для некоторых форматов отдельные повреждения могут остаться незамеченными, поскольку пиксельные данные не декодируются и не выполняется полная проверка всех контрольных сумм.

## 9. Установка и запуск

Требуется Python 3.10 или новее с Tkinter (в стандартной поставке Python для Windows).

Запуск из исходников:

```bash
python main.py
```

Сборка одного EXE-файла:

```bash
pip install pyinstaller
pyinstaller Lab2.spec
```

После успешной сборки файл будет находиться в `dist/Lab2.exe`. Консоль не показывается. В `Lab2.spec` сжатие UPX отключено.

## 10. Состав сдаваемой работы

- `main.py` — исходный код;
- `Lab2.spec` — конфигурация PyInstaller;
- `Lab2.exe` — исполняемый файл, полученный после сборки;
- `DOCUMENTATION.md` — сопроводительная документация.
