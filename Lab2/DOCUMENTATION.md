# Лабораторная работа 2. Чтение информации из графических файлов

## 1. Что делает программа

Десктопное приложение для Windows (Python + Tkinter). Пользователь выбирает папку (при желании вместе с подпапками, до 100 000 файлов), программа считывает из каждого графического файла основные сведения и показывает их в таблице:

| Колонка | Что означает |
|---|---|
| Файл | имя файла |
| Размер (px) | ширина × высота изображения в пикселях |
| DPI | разрешение (точек на дюйм) по горизонтали × по вертикали |
| Глубина цвета (бит) | число бит, которыми кодируется один пиксель |
| Сжатие | алгоритм сжатия данных в файле |
| Формат | реальный формат файла, определённый по содержимому |
| Дополнительно | доп. характеристики (см. раздел 4) |

Поддерживаются форматы: **jpg/jpeg, gif, tif/tiff, bmp, png, pcx**.

Удобства интерфейса: прогресс-бар и счётчик «обработано N из M», кнопка «Стоп», сортировка по клику на заголовок колонки, горизонтальная и вертикальная прокрутка, экспорт таблицы в CSV, красная подсветка нечитаемых файлов, итоговое время обработки.

## 2. Использованная внешняя библиотека и способ получения данных

Внешняя библиотека: **Pillow (PIL)**. Остальное: стандартная библиотека Python (`struct`, `os`, `threading`, `queue`, `concurrent.futures`, `tkinter`, `csv`).

Pillow открывает файл **лениво**: `Image.open()` читает только заголовок, а пиксели не декодируются (это происходит только при вызове `load()`, которого в программе нет). Поэтому обработка даже больших фотографий занимает миллисекунды.

Данные получаются двумя способами:

1. **Через Pillow**: размер (`img.size`), формат (`img.format`), DPI (`img.info`), теги TIFF (`img.tag_v2`), признак progressive у JPEG.
2. **Ручным чтением первых 4096 байт файла** (модуль `struct`) там, где Pillow выдаёт неточное значение. Это глубина цвета и сжатие для PNG, BMP, GIF, PCX и DPI для PCX. Причина: Pillow приводит изображения к «внутренним режимам» (например, 16-битный RGB PNG становится `RGB`, а серый PNG с 2 битами на пиксель становится `L`), поэтому глубину по режиму получить корректно нельзя.

## 3. Откуда берётся каждая основная характеристика

### Размер в пикселях
Берётся из заголовка файла средствами Pillow: JPEG хранит его в маркере SOF (Start Of Frame), PNG в чанке IHDR, BMP в BITMAPINFOHEADER, GIF в Logical Screen Descriptor, TIFF в тегах ImageWidth/ImageLength, PCX в полях Xmin..Ymax заголовка.

### Разрешение (DPI)
| Формат | Источник |
|---|---|
| JPEG | сегмент JFIF (APP0): плотность X/Y и единица измерения (1 = точек на дюйм, 2 = точек на см, пересчитывается ×2.54; 0 = только соотношение сторон, DPI нет), а также EXIF |
| PNG | чанк `pHYs`: пикселей на метр, пересчитывается в DPI делением на 39.37 (единица 0 = неизвестна, DPI нет) |
| BMP | поля biXPelsPerMeter/biYPelsPerMeter заголовка BITMAPINFOHEADER (пикселей на метр) |
| TIFF | теги XResolution (282), YResolution (283) и ResolutionUnit (296): 2 = дюйм (значение по умолчанию), 3 = сантиметр (пересчёт ×2.54), 1 = без единиц (DPI не показывается) |
| PCX | поля HDpi и VDpi в байтах 12–15 заголовка, читаются вручную |
| GIF | формат не хранит разрешение, показывается «—» |

Если разрешение в файле не задано, выводится «—», а не выдуманное число.

### Глубина цвета (бит на пиксель)
| Формат | Как определяется |
|---|---|
| PNG | чанк IHDR: байт 24 = бит на канал, байт 25 = тип цвета. Глубина = бит на канал × число каналов (серый 1, RGB 3, палитра 1, серый+альфа 2, RGBA 4). Для палитрового PNG это число бит индекса палитры (1, 2, 4 или 8) |
| BMP | поле biBitCount (байты 28–29) заголовка DIB (для старого OS/2-заголовка байты 24–25): 1, 4, 8, 16, 24, 32 |
| GIF | Logical Screen Descriptor: размер глобальной палитры = 2^(N+1) цветов, где N = 3 младших бита байта 10. Если у первого кадра есть локальная палитра, берётся она. Глубина = число бит индекса цвета (1–8) |
| TIFF | тег BitsPerSample (258): сумма бит по всем каналам (например, 8+8+8 = 24). Если указано одно значение, оно умножается на SamplesPerPixel (277) |
| PCX | байт 3 (бит на плоскость) × байт 65 (число плоскостей): 8×3 = 24 бита, 8×1 = 8 бит, 1×4 = 4 бита |
| JPEG | по режиму Pillow: градации серого 8 бит, YCbCr/RGB 24 бита, CMYK 32 бита (8 бит на компонент × число компонентов из маркера SOF) |

### Сжатие
| Формат | Что показывается |
|---|---|
| JPEG | сжатие с потерями на основе DCT (дискретного косинусного преобразования) + кодирование Хаффмана; режим *baseline* или *progressive* определяется по типу маркера SOF (SOF0 или SOF2) |
| PNG | всегда Deflate (единственный метод сжатия в спецификации, байт 26 IHDR = 0), без потерь |
| GIF | всегда LZW, без потерь |
| BMP | поле biCompression (байты 30–33): BI_RGB (нет), RLE8, RLE4, Bitfields, JPEG, PNG |
| TIFF | тег Compression (259): нет, CCITT (RLE, Group 3, Group 4), LZW, JPEG, Deflate, PackBits, JPEG 2000 и т.д. |
| PCX | байт 2 заголовка: 1 = RLE (кодирование повторов) |

## 4. Дополнительные данные (колонка «Дополнительно»)

Каждая выводимая характеристика поясняется:

| Характеристика | Что это, зачем нужна, откуда берётся |
|---|---|
| Тип цвета PNG (RGB, RGBA, палитра и т.д.) и бит на канал | IHDR, байты 24–25. Показывает, как интерпретировать пиксельные данные: есть ли альфа-канал (прозрачность), используется ли палитра |
| Adam7 (interlaced) | IHDR, байт 28 = 1. Постепенная загрузка изображения за 7 проходов, удобна для показа в браузере |
| Палитра: N цв. (GIF, BMP) | GIF: 2^(биты глобальной/локальной палитры). BMP: поле biClrUsed (байты 46–49), а если оно равно 0, то 2^biBitCount. Палитра — таблица цветов, на которую ссылаются индексы пикселей |
| interlaced (GIF) | бит 6 в Image Descriptor: строки хранятся в 4 прохода для постепенного показа |
| GIF87a / GIF89a | сигнатура версии формата (первые 6 байт). 89a поддерживает анимацию и прозрачность |
| анимация (GIF) | у файла больше одного кадра |
| top-down (BMP) | высота в заголовке отрицательная: строки хранятся сверху вниз (обычно снизу вверх) |
| DIB-заголовок N Б | размер структуры BITMAPINFOHEADER: 40 (базовый), 108, 124 (V4/V5 с цветовыми профилями) |
| OS/2 core header | старый 12-байтный заголовок BMP формата OS/2 |
| baseline / progressive (JPEG) | тип кодирования: последовательный или прогрессивный (изображение «проявляется» постепенно) |
| Adobe | в JPEG есть сегмент APP14 Adobe, характерный для CMYK/Photoshop-файлов |
| BlackIsZero, RGB, Palette, CMYK, YCbCr... (TIFF) | тег PhotometricInterpretation (262): как значения пикселей превращаются в цвета |
| страниц: N (TIFF) | число IFD (Image File Directory) в файле: TIFF может содержать несколько страниц/изображений. Размер и прочие данные показываются по первой |
| плоскостей, версия (PCX) | байт 65 (число цветовых плоскостей) и байт 1 (версия формата) |
| ⚠ расширение не соответствует формату | формат определяется по содержимому (сигнатуре), а не по расширению, например PNG-файл, переименованный в `.jpg` |

## 5. Быстродействие и интерфейс

- **Чтение только заголовков.** Из каждого файла читается не более 4096 байт заголовка, пиксельные данные не декодируются, файл закрывается сразу после чтения. Поэтому скорость определяется в основном диском, а не размером файла (папка в 2 ГБ обрабатывается так же быстро, как папка в 20 МБ с тем же числом файлов).
- **Многопоточность.** Анализ идёт в пуле потоков (`ThreadPoolExecutor`, число потоков = 2×ядра, но не больше 16). Ввод-вывод и разбор заголовков в Pillow освобождают GIL, потоки реально работают параллельно.
- **Интерфейс не блокируется.** Сканирование и анализ выполняются в фоновом потоке. Результаты передаются главному потоку через `queue.Queue`, а таблица обновляется таймером (раз в 30 мс, не более 300 строк за тик), чтобы Tkinter успевал отрисовываться даже при десятках тысяч файлов.
- **Прогресс.** Пока идёт сканирование папки, полоса бегает (indeterminate); после подсчёта файлов переходит в режим «N из M» и доходит до 100%.
- **Защита от двойного запуска.** Кнопка «Анализ» блокируется на время работы; результаты старого запуска отбрасываются по номеру запуска. Кнопка «Стоп» и закрытие окна корректно прерывают работу.
- **Проверка на тестовых данных.** Автоматически сгенерированы тестовые файлы всех форматов (разные режимы: 1/8/16/24/32 бита, палитровые, CMYK, TIFF с компрессией none/LZW/PackBits/Deflate/JPEG, PCX 8/24 бита), а также нулевой файл, обрезанный PNG и текст, переименованный в `.jpg`. Все значения совпали с ожидаемыми. На 1500 JPEG (800×600) обработка заняла 0.3 с.

## 6. Обработка ошибок

Любой файл, который не удалось разобрать (пустой, обрезанный, не изображение), не прерывает работу: в таблицу добавляется красная строка с пометкой «Ошибка: не является изображением или повреждён». Ошибки доступа к папкам при сканировании пропускаются, общие ошибки показываются в диалоге.

## 7. Ограничения

- У многостраничных TIFF и анимированных GIF показываются сведения о первой странице/кадре.
- Файлы определяются по расширению для отбора в список (jpg, jpeg, gif, tif, tiff, bmp, png, pcx), формат внутри файла определяется по содержимому.
- Глубина цвета JPEG определяется по режиму, который определил Pillow (редкие 12-битные JPEG не поддерживаются Pillow).

## 8. Сборка и запуск

```
pip install pillow pyinstaller
python main.py                 # запуск из исходников
pyinstaller Lab2.spec          # сборка exe: dist/Lab2.exe
```

`Lab2.exe` собирается в один файл без консоли, Python на целевом ПК не нужен. UPX сжатие в `Lab2.spec` отключено, чтобы антивирусы не принимали exe за вредоносный.

## 9. Состав сдаваемой работы

- `Lab2.spec` — конфигурация сборки PyInstaller
- `Lab2.exe` — собранное приложение (после `pyinstaller Lab2.spec`)
